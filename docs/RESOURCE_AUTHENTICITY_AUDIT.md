# Resource authenticity audit — 3 November 2026

This is an integrity and provenance audit, not subject-expert certification. Counts are from read-only queries against the configured database at Alembic revision `0003_content_engine`; no production data was changed. Local code and the bundled content pack were inspected separately. Deployed configuration and the content of every question were not independently verified.

## Diagnostic questions

- The implementation selects active, published questions from the selected curriculum; classroom-scoped questions are included only in their classroom. It requires 20 questions and uses the final five to focus on weaker assessed skills. Database persistence does not establish educational quality or NCERT provenance.
- The configured database contains 2,028 published, active questions with an English translation. An earlier fingerprint audit matched 1,914 English prompts and codes exactly to the repository's generic question generator. Those matches are generated templates, not evidence of teacher verification. The other 114 are not automatically verified: they simply did not match this fingerprint.
- All 2,028 published English MCQs have exactly one correct option flag, and 2,028 have a Hindi translation. An aggregate check found no question with conflicting correct-option IDs between languages. This checks structural consistency only; it does not establish that answers, translations or explanations are academically correct.
- The separate `verified_answer` field is empty in the inspected legacy records; grading uses the option's `is_correct` flag. The review interface now derives the selected answer from that flag when the field is empty. A subject expert must review the actual option content and explanation.
- Migration `0012_review_generated` is prepared to put fingerprint-matched questions in review. It has been dry-run with rollback but is not deployed. At the prior audit snapshot, applying it would leave sufficient published questions for a 20-question diagnostic in only 2 of 25 grade/subject combinations, until more content is reviewed.

## Bundled material and curriculum

- The bundled Class 8 mathematics pack contains 200 questions, all marked draft and requiring teacher review. None of those question entries contains a source, reference, citation or source URL field. The pack labels itself NCERT, but that label is not proof of provenance, syllabus alignment or endorsement.
- Curriculum lists and skill names in the repository have not been individually checked against current official textbook editions or a teacher-approved syllabus. The [official NCERT textbook portal](https://ncert.nic.in/textbook.php) can be used as a reference; its publication and reuse terms must be checked before distributing textbook content.
- Classroom lessons are teacher-authored in the local implementation. The configured database is still at revision `0003`, and its classroom lesson table does not exist. There is no evidence in this audit that a reviewed lesson bank has been loaded.

## Student and teacher data

- The configured database contains five teacher accounts matching emails in `seed_5_teachers_cohorts.py`, 15 usernames matching `seed_real_cohort.py`, six classes assigned to the matching teacher accounts, 261 enrollments in those classes, and 11 assignments in those classes. An identifier-pattern query found 2,787 attempts matching the format generated by the five-cohort seed script; no attempts had the explicit `seed-` prefix used by the other script.
- The seed scripts generate users, enrollments, mastery and attempts. Matching accounts, classes or patterns are strong indicators of seeded data, but do not by themselves prove that every later action by those accounts was synthetic. Preserve records until an authorized owner reviews provenance; do not delete or reclassify them automatically.
- Teacher-authored assignments and real student submissions cannot be certified as genuine solely from table membership. Separate seeded records from verified classroom usage through an owner-led review and appropriate provenance records.

## Tutor and remaining limitations

- In the local API configuration, the tutor provider is `mock` and no OpenAI key is configured. This describes the checked local settings, not the deployed service's configuration. The provider factory otherwise falls back to the mock provider when no configured OpenAI key is available.
- Automated checks cannot establish correctness across 25 grade/subject combinations or certify NCERT alignment. Subject experts need to review questions, correct choices, solutions, Hindi translations, difficulty and current syllabus coverage before publishing. Missing classroom lessons must be authored or sourced and reviewed.
- The diagnostic, dashboard, import and review changes in the workspace are not yet deployed to the configured database. Browser end-to-end testing against a real updated database remains outstanding.
